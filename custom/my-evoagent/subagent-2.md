**题目**：独立 SubAgent 做对抗验证，但用的是同一个大模型，凭什么算独立？

### 回答

这是这个项目**最强的反杀题**，因为面试官在测你会不会吹。

**这道题的陷阱**：让你去论证"独立 SubAgent 就客观了"。如果你真这么答，面试官马上反问"同一个模型，参数都一样，独立在哪？"—— 你就被将死了。

**正确的答题结构分三步**：

**第一步：主动承认局限。**
同一个基座模型，参数化知识完全一样，**确实不存在真正独立的判断**。先把这个说透。**这一步必须由你主动说，不能等他追问。**

**第二步：说明你的设计在哪个层面追求"独立"。**

"我的做法是**信息层面的隔离，不是模型层面的独立**。验证 SubAgent 是**独立上下文**的新 Agent 实例，它拿不到主 Agent 的推理过程，只拿到最终输出和工具日志。所以它不知道主 Agent 是怎么'说服自己'的，只能就事论事地挑刺 —— 确认偏误的传播靠的是推理链，切断推理链就切断了传播路径。"

**具体实现**（要能说出细节）：
- **触发时机**：任务尾巴上强制拉起，不是可选项。
- **输入**：**只读最终输出 + 工具执行日志**，不给推理链。
- **职责**：对照工具输出和最终结论是否一致、有没有跳过关键步骤。
- **配套的硬拦截**：Plan 模式下 Agent 声称完成时，`no_tool` 会**拦截** —— 如果没有给出 `VERDICT`、或者没有启动验证 SubAgent，就强制继续执行。这让"验证"从建议变成了必经流程。

**第三步：交代代价和边界。**

"这个设计**增加了延迟**，因为多了一个完整的 Agent 回合。但我认为值得 —— 它显著减少了'看起来对其实错'的情况。"

**边界**：明显的不一致能抓出来，但**模型共同的知识盲区抓不出来**。这个边界要主动说。

**你的答题金句**（原话，可以直接用）：
"**Agent 工程最难的不是做对，而是做错时能发现、能恢复、能审计。**"
