**题目**：L0 到 L4 的分层记忆分别是什么？

### 回答

这是必答题，答不清全盘皆输。**核心要讲清楚一件事：这是文件化记忆，不是向量库**。

**分层定义**（背下来）：

| 层 | 载体 | 存什么 | 读写方式 |
|---|---|---|---|
| **L0** | `memory_management_sop.md` | **记忆更新规程** —— 定义什么该记、怎么记 | 触发记忆结算时读入 prompt，作为本次更新的操作指引 |
| **L1** | `global_mem_insight.txt` | **索引** —— 有哪些 L2/L3 文件、各自关键词 | 拼进 system prompt 开头，让 Agent 知道"我有哪些记忆可用" |
| **L2** | `global_mem.txt` 等 | **已验证事实** —— 路径、账号、用户偏好、环境约定 | `file_patch` 增量修改，只追加不删除 |
| **L3** | `memory/*.md`、SOP 文件 | **任务 SOP / Skill** —— 踩坑步骤、前置条件、经验总结 | 任务前按需 `file_read`；任务成功后精简写入 |
| **L4** | `L4_raw_sessions/` | **历史会话归档** | 定时把模型响应目录压缩摘要，12h cron |

**外加一层 Working Memory**：`handler.working` + Session history，存当前任务的 `key_info`、plan 模式状态、近轮对话。每轮通过 anchor prompt 注入。

**分层的依据**：**信息的稳定性和读取时机**。L1 是导航层（永远要在 system prompt 里），L2 是稳定事实（改了才读），L3 是任务级 SOP（按任务类型检索），L4 是归档（基本不主动读，用于审计和回溯）。

**为什么用文件而不是向量库？**（这是最关键的一个追问，一定要准备）

"科研和工程场景的事实要**可编辑、可审计**。向量库里改一条记忆是黑盒操作 —— 你不知道改了哪一维、影响哪些检索结果。文件是明文，改了什么一目了然，出问题能 diff、能回滚。而且 L1 索引层做定位比 embedding 更准 —— 我知道我要找的是'某类任务的 SOP'，直接按文件名和关键词定位，不需要语义相似度。"

**自我进化闭环**（面试官必问的下一步）：
任务成功 → Agent 调 `start_long_term_update` → 按 L0 规程判断这次经验属于哪类 → **最小局部** `file_patch` 更新 L2，或新建/修改 L3 的 SOP → 同步更新 L1 索引。

**三层过滤防污染**（这题答出来是加分项）：
1. **任务成功且通过独立 SubAgent 验证** —— 失败任务的经验不结晶。
2. **路径可结构化复用** —— 剥离本次特有参数后，流程是否还对其他任务成立。
3. **同类任务 ≥2 次才结晶** —— 防止一次性的偶然成功污染技能库。

**常见追问**：
- 「L0 为什么单独作为一层？」→ 因为更新规程本身也需要被管理。如果把"什么该记"写死在代码里，策略调整要改代码；写成 SOP 文件，改记忆策略就是改一个 Markdown。
- 「L2 只追加不删除，不会越来越长吗？」→ 会。所以 L2 的写入有准入判断（走 L0 规程），而且同类事实会被 `file_patch` 原地更新而不是新增一条。
- 「L3 会不会和 L2 重叠？」→ 分工是 L2 存"是什么"（事实），L3 存"怎么做"（流程）。同一件事的事实和做法分开放，读取时机也不同。
