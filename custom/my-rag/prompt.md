**题目**：微调有没有必要？Prompt 工程是不是就够了？

### 回答

**分情况，而且要明确"能 Prompt 解决就不微调"这个立场**。

如果只是格式问题，Prompt 加强约束加后处理正则，往往性价比更高 —— 成本低、迭代快、不需要 GPU。所以面试官问"为什么不直接 Prompt 解决"，你要先认同这个前提，再说明你**为什么仍然选择了微调**。

**你选择微调的理由需要你自己组织**（通用的论证方向）：规则约束在长回答里会失效（模型前段遵守、后段失控）、交付给他人长期使用需要稳定性、或者格式复杂度超过 Prompt 能稳定约束的范围。

**必须补一句边界**：微调不是所有 RAG 项目的必选项。如果需要，就诚实说"这个场景下 Prompt 也够用，但为了交付稳定性我选择了微调"。
