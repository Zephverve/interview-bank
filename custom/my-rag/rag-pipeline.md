**题目**：完整讲一遍 RAG 的链路，每一步的关键决策是什么？

### 回答

按你的实际系统讲，逐段给决策点。

| 环节 | 关键决策 | 你的选择与理由 |
|---|---|---|
| **解析** | 用什么解析器？ | MinerU，因为科研论文双栏+公式+表格多，通用解析器会串行 |
| **切片** | 切多大？重叠多少？ | Parent-Child 分层：子块 512 token 用于检索，父块 2k token 用于生成 |
| **索引** | 用什么向量库？索引类型？ | Qdrant；考虑增量更新能力 |
| **召回** | 单路还是多路？ | Dense + BM25 + Sparse 三路 |
| **融合** | 怎么合并多路结果？ | RRF |
| **重排** | 要不要重排？ | Cross-Encoder 重排 |
| **生成** | 怎么保证不编造？ | Faithfulness Guard + 引用溯源 |
| **评测** | 怎么知道有效？ | 120 问黄金集 + Recall@5 |

**追问预判**：
- 「为什么子块检索、父块生成？」→ 检索要精确（块小语义集中），生成要上下文完整（块大有上下文）。这是**解耦检索粒度与生成粒度**的标准做法。若直接用小块的文本生成，会丢失上下文导致答非所问。
- 「父块会不会超出上下文窗口？」→ 会，所以我限制了单次注入的父块数量并做长度截断。
