**题目**：Recall@5 从 0.51 提升到 0.85，逐步怎么来的？

### 回答

几乎必问，且会追问到底。**必须能给出分步消融**。

**消融表**（报简历口径，直接背）：

| 阶段 | 配置变化 | Recall@5 | 增量 |
|---|---|---|---|
| 基线 | basic 解析 + dense 单向量 + Top-5 + 裸 prompt | 0.51 | — |
| + 混合检索 + Cross-Encoder 重排 | Dense + BM25 + Sparse 三路召回，RRF 融合后重排 | ~0.71 | +0.20 |
| + Agentic + MinerU + Guard | Agentic 编排（改写 / HyDE / 门控 / re-retrieve）+ MinerU 结构化解析 + Faithfulness Guard | **0.85** | +0.14 |

**关键话术**：
- 基线配置必须说清楚 —— 0.51 是"最朴素的 RAG 做法"，没有混合检索、没有 Guard，是我要超越的起点。
- 每一步要能说出**它解决什么问题**，而不只是给数字（混合检索解决术语精确匹配，重排解决 Top-K 排序噪声，Agentic 解决多跳和问不对题，MinerU 解决双栏公式解析错误）。
- 主动补一句："**Recall@5 只是召回侧指标，我也关注端到端答案质量和延迟。指标变好不等于系统变好。**"

**追问预判**：
- 「120 条评测集怎么构建的？分布合理吗？」→ 通用原则是**按问题类型分层**（事实型/概念型/对比型/多跳型/无答案型），且覆盖不同来源。**具体怎么分的，按你的实际情况答。**
- 「评测集有没有可能过拟合？」→ 会。缓解：调参只在一个子集上做，其余留作验证；评测集定期更新版本。
- 「0.85 在工业界算什么水平？」→ **指标要放在场景里看**。科研文献场景术语密集、长尾强，比查询集中的场景更难拿高召回。不要主动报你没实测过的其他场景数字。
