**题目**：HyDE 的原理是什么？什么情况下会失效？

### 回答

**原理**：让 LLM 先根据 query **编一段假想的答案文档**，然后用这段假文档的向量去检索，而不是用 query 的向量。

为什么有效？因为**真实答案文档的措辞风格和"提问"差异很大，但和"假想答案"很接近**。用户提问用疑问句、口语化；论文正文是陈述句、学术化。两者在嵌入空间里距离远。而 LLM 生成的假想答案，风格上更接近真实文档，所以能拉近距离。

**失效场景**（这部分才是重点，答出来才叫懂边界）：

**专有事实失效** —— LLM 不知道的东西编不出来。你问某篇论文提出的新方法，LLM 没见过，生成的假文档会把检索带偏。这在科研场景特别危险，因为论文里的方法名对模型来说几乎全是新词。

**精确匹配场景失效** —— 编号、公式、数据表，HyDE 会把简单问题复杂化。用户明明在找一个特定的公式，你生成一段泛泛的假想内容，反而降低了精确命中的概率。

**延迟敏感场景失效** —— 多一次 LLM 调用，首字延迟增加一到两秒。

**幻觉放大** —— 假文档一旦跑偏，会把检索引到完全无关的领域，而且这个错误是静默的。

**所以我实际是用条件触发，不是无脑全用。** 意图路由先判断问题类型：**事实型、编号型直接走混合检索，只有开放解释型和概念对比型才启用 HyDE**。这个取舍很重要 —— 不是堆技术，而是知道什么时候不用。
