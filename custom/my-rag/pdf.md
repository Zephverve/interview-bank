**题目**：数据入库前怎么处理噪声？PDF 各种格式怎么处理？

### 回答

- **PDF 解析的坑**：双栏排版（通用解析器会左右栏串行）、公式（转成文本后失去语义）、表格（行列结构丢失）、页眉页脚（混进正文）、参考文献（大量低价值文本进入索引）。
- **三级降级策略**：优先 MinerU 结构化解析 → 失败退回通用 PDF 文本抽取 → 再失败做 OCR。**降级要有日志**，用于事后分析哪类文档解析质量差。
- **入库前的清洗**：
  1. **元数据剥离**：页眉页脚、页码、期刊版权声明正则过滤。
  2. **参考文献单独处理**：不参与语义检索（噪音大），但保留用于引用匹配。
  3. **质量过滤**：解析后 chunk 太短（<50 字符）或纯符号的直接丢弃。
  4. **知识抽取**：对关键字段（标题、作者、年份、方法名）做结构化抽取，写入 metadata，供过滤检索用。

**追问预判**：
- 「把错误文档入库了怎么办？」→ 需要**版本控制和审计**：每条 chunk 记录来源文档 ID + 入库时间 + 操作者；支持按文档 ID 批量回滚（删除该 doc_id 及其派生实体）；入库走**审核流程**（至少是"可追溯"），关键知识库做人工确认。
