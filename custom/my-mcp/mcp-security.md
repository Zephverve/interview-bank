**题目**：MCP 的安全问题有哪些？怎么防御？

### 回答

三类攻击，每个都要能说清机制。

1. **Tool Poisoning（工具投毒）**
   - **机制**：恶意指令藏在**工具描述/元数据**里。用户 UI 只显示简短摘要，但**模型读的是全文**，从而被操纵。**甚至不需要真正调用该工具，载入上下文即生效**。
   - 衍生 **Rug Pull**：安装时描述干净、获批后篡改。
   - 进一步有 **Full-Schema Poisoning**：参数名、参数描述、默认值、enum、错误信息 —— **每个文本字段都是注入面**。已被 OWASP 收录为 MCP03:2025。
   - **防御**：把工具描述**当作不可信输入**而非可信文档；**Tool Pinning**（对描述做哈希，变更就拒绝执行并重新审批）；完整 schema 审查；按任务做最小权限 allow-list；不可逆操作强制人工确认。

2. **Confused Deputy（混淆代理）**
   - **机制**：攻击者利用 MCP 代理服务器的静态 Client ID + 动态客户端注册 + 第三方同意 Cookie，在用户不知情下拿到授权码，换取 token 以用户身份访问第三方 API。
   - **防御**：维护按客户端的同意注册表并在发起授权前校验；**redirect_uri 精确字符串匹配（禁通配）**；`state` 加密随机、单次使用；同意 Cookie 用 `__Host-` 前缀 + `Secure`/`HttpOnly`/`SameSite`。

3. **Token Passthrough（令牌透传）**：Server 接受未颁发给自己的令牌并透传下游 —— **规范明确禁止（MUST NOT）**，会绕过限流和审计、破坏信任边界。

**加分观点**：**MCP 的安全问题不是实现 bug，是信任模型的架构级问题**。Tool Poisoning 恰恰是"协议按设计正常运行"的情况下发生的。规范自己都承认"MCP 无法在协议层强制执行安全原则"，只能要求实现方自建同意/授权流。
