**题目**：为什么选 LangGraph，不选 AutoGen / CrewAI / 手写？

### 回答

| 框架 | 定位 | 适合 | 不适合 |
|---|---|---|---|
| **LangGraph** | 图编排，显式状态机 | 需要精确控制流程、有清晰状态流转、要可恢复 | 需要高度动态的临时组队 |
| **CrewAI** | 角色扮演式协作 | 快速搭角色分工明确的团队（researcher/writer） | 精细干预、复杂条件分支 |
| **AutoGen** | 对话驱动的多 Agent | 需要 Agent 之间多轮讨论、代码执行 | 流程确定性要求高的生产系统 |
| **手写** | 完全可控 | 学习原理、需要特殊控制（如我的运行时干预） | 交付速度、团队协作 |

- **我的选择依据**：
  - RAG 系统用 **LangGraph**：因为流程是"有明确节点和条件边的状态机"，图模型天然贴合，且支持 checkpointer 做中断恢复。
  - EvoAgent 用**手写**：因为我要研究 Agent 内部机制，且需要框架不支持的运行时动态干预。
- **一句话立场**：**框架解决的是"少写代码"，不是"想不清楚"**。选框架前先把状态和流转想明白，否则换框架也救不了。

**追问预判**：
- 「如果要快速交付一个业务，你选哪个？」→ CrewAI，角色分工的抽象最贴近业务语言，上手最快。但要注意它的抽象在复杂分支场景会变成束缚。
