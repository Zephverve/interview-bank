**题目**：大模型幻觉怎么解决？RAG 检索到正确信息但仍然编造怎么办？

### 回答

分层治理，从数据端到输出端。

| 层级 | 手段 | 解决什么 |
|---|---|---|
| 检索端 | 混合检索+重排，提高上下文信噪比 | 上下文里就没有正确的依据 |
| 上下文端 | 分块标注引用 ID，明确"只依据以下材料回答" | 模型把参数化知识混进来 |
| 生成端 | 低 temperature + 强约束 Prompt + 结构化输出 | 自由发挥 |
| 校验端 | Faithfulness Guard：逐句检查是否有原文依据 | 生成后才发现的编造 |
| 兜底端 | 无依据时明确拒答，引导用户补充 | 宁可不说不可乱说 |

- **最关键的**：检索到了正确信息仍然幻觉，根因通常是**上下文里正确信息和噪声混在一起，模型抓错了**，或者**Prompt 没有强约束"只能基于材料回答"**。
- 可复现的定量：加了输出自校验（Faithfulness Guard）之后，编造类回答的占比从两位数降到个位数。**面试官会追问具体数字，准备好绝对值**。

**追问预判**：
- 「Faithfulness 怎么算？」→ 把答案拆成原子claim，逐个判断能否在检索到的上下文里找到支撑，支撑率 = 有依据的 claim 数 / 总 claim 数。低于阈值就触发重生成。
- 「这个判断本身也是 LLM 做的，它也会错吧？」→ 会，这是这套方案的软肋。缓解方式是降低了判定难度（只做"能否找到支撑"的二分类，不做开放式评价）+ 抽样人工复核。
