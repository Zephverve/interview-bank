**题目**：ReAct 的原理是什么？除了 ReAct 还有哪些 Agent 范式？

### 回答

| 范式 | 机制 | 优势 | 劣势 |
|---|---|---|---|
| **ReAct** | Thought-Action-Observation 交替循环 | 灵活、可解释、每步有依据 | 步数不可控、易陷入局部循环 |
| **Plan-and-Execute** | 先出完整计划再逐步执行 | 全局性好、可并行 | 计划一旦错就全错，重规划成本高 |
| **Reflection / Reflexion** | 执行后自我批判再重试 | 能自我纠错 | 反思结果会污染上下文，成本翻倍 |
| **Multi-Agent** | 多角色分工协作 | 可拆解复杂任务 | 通信开销大、易死循环、幻觉放大 |

- 强调：**范式不是互斥的**，你的 EvoAgent 是 Plan-and-Execute 打底（四阶段 SOP）+ Reflection（对抗验证）混合。

**追问预判**：
- 「Reflection 会不会把错误反思写进上下文，越反思越错？」→ 会，这是这个范式固有的风险。**你的项目里怎么处理的，按实际情况答。** 通用思路是让反思结果不直接回流主上下文（比如先写成结构化的问题清单，只把"发现了什么问题"传下去，不传原始反思文本）。
> ⚠️ 如果你项目里没做这个处理，就如实说"这是个已知风险，我当时没做特别处理"，然后讲你会怎么改。
