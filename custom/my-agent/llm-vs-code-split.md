**题目**：你的 Agent 项目里，哪些环节交给 LLM 决策，哪些是确定性代码？为什么这么切？

### 回答

- **交给 LLM 的**：任务意图理解、探索阶段的信息搜集方向、Plan 生成、执行中的工具选择、验证阶段的问题发现。
- **写死的**：阶段状态机流转、SubAgent 生命周期管理、记忆的读写落库、上下文压缩的触发阈值、工具的参数 schema 校验、错误重试次数上限。
- 切分原则三条：
  1. **要判断力的给 LLM**，要一致性的给代码；
  2. **涉及资源分配和安全边界的必须写死**（最大步数、最大 Token、危险工具白名单）；
  3. **可验证的输出必须结构化**（用 Pydantic 约束，不通过就重试）。

**追问预判**：
- 「你怎么保证 LLM 输出的结构化？失败了怎么办？」→ Pydantic 校验 + 失败带错误信息重试（最多 2 次）+ 最终降级到默认策略，并记录失败日志用于事后分析。
