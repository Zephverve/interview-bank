**题目**：Agent 怎么判定自己的执行结果是对的？

### 回答

分层判定，从硬到软。

| 层 | 判定方式 | 可靠性 | 适用 |
|---|---|---|---|
| **语法层** | 结构校验（JSON schema、代码能否编译） | 最高 | 有明确格式要求的输出 |
| **执行层** | 实际运行（代码跑测试、SQL 能否执行、API 返回码） | 高 | 可执行产出 |
| **规则层** | 断言校验（数值范围、字段完整性、业务规则） | 高 | 有明确规则的场景 |
| **检索层** | 事实核查（结论能否在源材料里找到支撑） | 中 | 知识类任务 |
| **模型层** | LLM 评审（多维度打分） | 低-中 | 主观质量 |
| **人工层** | 人在回路确认 | 最高 | 高风险操作 |

- **核心观点**：**判定可靠性是递减的，所以优先用便宜且确定的层**。能用 schema 校验的绝不问 LLM，能跑测试的绝不靠模型自评。LLM 判定只用在前面几层都覆盖不到的"质量/合理性"维度。
- 补充：**判定必须有明确的失败处置**，否则验证就是走过场。失败 → 重试 / 换策略 / 降级 / 上报人工，四选一。
