**题目**：这个项目你的主要贡献是什么？

### 回答

**先说清楚团队结构**：这是**三人竞赛项目**，我是**建模与实现**这一环 —— 也就是把方案落成能跑通、能出分的代码。另外两位队友负责的是方案调研与对比、结果分析与报告撰写这部分。

**我具体做了这些**（按工程链路讲，这样最自然）：

| 环节 | 我做的事 |
|---|---|
| **数据流水线** | CT 影像 + RTSTRUCT 标注的读取与对齐、窗宽窗位归一化、数据划分。**这是所有后续工作的地基** —— 标注和影像对不齐，后面全白做 |
| **模型实现** | SPADE + MoE 结构的代码实现、训练脚本、两阶段训练的串联（阶段一权重如何接到阶段二） |
| **切片与融合** | 3D 体数据按 2D 切片处理、滑窗推理、**高斯权重融合**消除拼接缝、连通域筛选与形态学后处理 |
| **指标评测** | Dice / Recall / 过勾体积比的实现与逐阶段对比 |

**现场怎么讲**（一句到位）：

> "这个项目我负责的是**建模和实现代码** —— 数据流水线、SPADE+MoE 的实现、两阶段训练、滑窗推理和高斯融合、指标评测都是我在做。方案层面是三个人一起讨论定的。"

**这么讲的好处**：既**准确**（不说"整个模型是我原创设计的"），又**有说服力**（实现能力是实打实的）。

**会被追问的点，提前准备**：

- 「SPADE 和 MoE 是你设计的吗？」→ **如实说是方案对比后选定的结构**，但强调**实现和调优是你做的**：为什么最终选 SPADE 而不是 U-Net 或 nnU-Net、MoE 的三个专家怎么切分、训练过程中调了哪些东西。**"选型理由 + 实现细节"比"原创性"更好答，也更容易讲出信息量。**
- 「你负责实现，那你懂为什么要用 MoE 吗？」→ 必须能讲清楚（见上文"为什么用 MoE"那一题）。**实现者不等于执行者**，能讲清设计意图才是加分项。
- 「高斯融合是你想出来的吗？」→ 这是工程上的常见做法（滑窗推理的标准操作），**不要声称是原创**。正确答法："这是滑窗推理处理边界问题的通用做法，我用它解决了窗口边界拼接缝的问题。"

**收尾**（自然转场，别让面试官在这题上耗太久）：

> "这个项目的价值是让我完整走了一遍**从数据处理到模型实现到指标评测**的链路，动手能力是练出来的。但它不是我的主攻方向 —— 我投的是 Agent / RAG 方向，那边我有更完整的系统级经验。"

**为什么这题要谨慎**：面试官问"你的贡献"就是要**剥掉团队成果、定位你个人**。说"我负责建模实现"是准确且有力的；但如果夸大成"结构是我设计的"，追问架构细节时就会露馅。**你负责实现这件事本身完全够看，不需要加码。**
