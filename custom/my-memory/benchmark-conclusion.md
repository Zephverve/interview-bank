**题目**：横向评测的结论是什么？哪个引擎更强？

### 回答

这是最能证明这段实习产出的一题 —— **我确实跑出了可比的横向数据**。

**设置**：LoCoMo 全量 10 段对话、**1986 道题**，五个类别（单跳 / 时序 / 常识 / 多跳 / 对抗），同一套 LLM 与 Embedding 配置（这正是 Config 层存在的意义），Graphiti 与 LightRAG 逐一跑完。

**结果**（按类别拆，这样比只报一个总分更有说服力）：

| 类别 | Graphiti | LightRAG | 题数 |
|---|---|---|---|
| 单跳 single_hop | 0.603 | **0.737** | 282 |
| 时序 temporal | 0.770 | **0.770** | 321 |
| 常识 commonsense | **0.526** | 0.469 | 96 |
| 多跳 multi_hop | 0.817 | **0.848** | 841 |
| 对抗 adversarial | 0.713 | **0.832** | 446 |
| **加权总体** | 0.742 | **0.797** | 1986 |

**结论要讲得有信息量，不能只说"LightRAG 赢了"**：

> "LightRAG 在总体和多数类别上领先（0.797 vs 0.742），**优势最明显的是对抗类问题（0.832 vs 0.713）** —— 也就是"问了一个根本没记录过的事，能不能老老实实说不知道"。这个差距说明 LightRAG 的检索在「无相关证据」时更倾向于返回空，而不是硬凑一个相似片段给模型，减少了幻觉。而 Graphiti 只在常识类上反超，这类题本来就更依赖模型的世界知识而不是记忆本身。"

**再补一句深度判断**（把话题引到你的主场）：

> "但我不会说 LightRAG 全面更好。**两个引擎的差距在不同类别上是不均匀的** —— 时序类打平，说明它们处理时间信息的能力接近；真正的分化在对抗和多跳。如果要选型，我会按**业务的主要提问类型**来决定，而不是看总分。"

这样答完整覆盖了「设置 → 数据 → 结论 → 判断」四层，面试官很难再追问出漏洞。

**可能的追问**：

- 「1986 道题怎么来的？」→ LoCoMo 官方全量数据集，一段对话 80–120 题，10 段合计约 2000 题。
- 「为什么多跳类题数（841）这么多？」→ 这是 LoCoMo 数据集的固有分布，**不是我挑的**；我在报结果时按类别拆开，就是为了避免用不均匀的分布误导结论。**这一点主动说，反而显得严谨。**
- 「这个分数算什么水平？」→ 不主动对标论文数字（我跑的是"统一封装层 + 同一套 LLM 配置"下的工程复现，**配置和原论文不一定对齐**，直接比不公平）。安全说法是"我做的是**内部横向对比**，结论是相对排名，不是绝对水平"。
