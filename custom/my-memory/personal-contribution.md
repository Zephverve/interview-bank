**题目**：三个月实习做这么多引擎接入，哪些是你真正做的？

### 回答

这个问题必须主动说清楚，因为面试官一定会怀疑这个时间跨度。

**先说结论：这个项目是我独立做的** —— 从架构设计到代码实现到评测，一个人完成。

但**"独立做"不等于"从零造引擎"**，这个边界必须自己先划清楚，否则面试官一追问就尴尬。准确的说法是：

| 层次 | 是不是我写的 | 怎么讲 |
|---|---|---|
| **四个记忆引擎本体**（Graphiti / LightRAG / Mem0 / Hindsight） | ❌ 开源实现 | 我用的是它们的官方 SDK / 包，**核心算法不是我的** |
| **统一运行时层**（Adapter / Router / Config / API / CLI / 前端 / 评测套件） | ✅ 我写的 | 这是我这段实习的核心产出 |
| **底层算法理解**（Graphiti 的双时态、LightRAG 的图检索） | ⚠️ 理解并适配，非原创 | 要能讲清原理，但不能说成自己设计的 |

**主动划界的话术**（可以直接讲）：

> "这个项目的记忆引擎本身是四个开源实现，我没有重造轮子 —— 我做的是**把它们统一封装成一个可切换、可对比的运行时**。价值在于：一套 API 能跑四个引擎，同一份评测数据能产出可比的横向结果。"

这么讲有两个好处：**一是显得懂工程**（知道什么时候不该重复造轮子），**二是把追问引到你的主场** —— 面试官接着会问"你怎么统一封装的"，那正是你准备最充分的部分。

**会被追问的三个点，先想好**：

1. 「为什么选这四个引擎？」→ 要能说清各自的定位差异：Graphiti 偏时序知识图谱、Mem0 偏用户偏好抽取、LightRAG 偏文档知识库、Hindsight 是另一套 retain/recall 范式。**选它们是因为它们代表了不同的记忆设计哲学，正好用来做横向对比。**
2. 「为什么需要统一封装？」→ 见上文——避免技术选型被单引擎绑死，同时获得**可对比 / 可替换 / 可组合**三个收益。
3. 「评测结论是什么？谁赢了？」→ 见下一条（有真实数据）。
