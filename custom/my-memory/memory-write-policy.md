**题目**：记忆写入策略：什么该记、什么不该记？

### 回答

**该记的**：
1. 用户明确的偏好和约束（"以后都用中文回答"）
2. 稳定事实（项目名、路径、接口约定）
3. 已验证的成功经验（SOP、踩过的坑及解法）
4. 任务级结论（"X 方案在 Y 条件下可行"）

**不该记的**：
1. 一次性上下文（本次任务的具体参数）
2. 未经证实的推断（LLM 自己猜的）
3. 时效性数据（今天的天气）
4. 敏感信息
5. **已经被后续信息推翻的旧结论**

**准入机制**：写之前过三道判断——① 是否已在库中（去重）② 是否与既有记忆冲突 ③ 是否满足"未来可复用"的标准。第三点最容易被忽略：**判断标准是"下次遇到类似任务，这条信息能减少多少探索成本"**。

**追问预判**：
- 「怎么自动判断该不该记？」→ 常见做法是**任务成功信号 + 复用性判别（LLM 打标）+ 人工审核兜底**。纯自动会有噪声，所以初期通常是小规模高置信度入库。
> ⚠️ **你的实际准入机制是什么？** 按真实情况答。
