**题目**：LoCoMo / LongMemEval 评测怎么做？LLM Judge 的分数你信吗？

### 回答

- **评测流程**：构造多轮长对话 → 写入记忆引擎 → 在后续轮次提问（考察是否记住了早期信息）→ 收集引擎生成的答案 → LLM Judge 按维度打分（正确性、完整性、无幻觉）→ 汇总对比。
- **LoCoMo** 侧重长对话记忆的问答；**LongMemEval** 侧重长期记忆的五种能力（信息抽取、多会话推理、知识更新、时间推理、拒绝作答）。
- **LLM Judge 的可靠性问题**（面试官想听这个）：
  1. **位置偏见**：Judge 倾向选先出现的选项 → 缓解：**交换 A/B 顺序测两次，结果一致才算数**。
  2. **长度偏好**：长答案得高分 → 缓解：Prompt 里明确"不要因长度加分"，或多维度分开打分。
  3. **自我增强偏见**：Judge 偏好和自己同族的模型输出 → 缓解：用**不同的 Judge 模型**跑，对比一致性。
  4. **绝对分数无意义**：跨模型比较看相对排名，不看绝对值。
- **我实际怎么做的**：**人工抽检没做**（如实说）。替代做法三条：① 能用规则算的绝不用 LLM（token F1 / EM / ROUGE）；② Judge 短路逻辑 —— 精确匹配 / 日期格式等价 / Yes-No 极性一致时直接给分，不调 LLM；③ 五档离散分（0/0.25/0.5/0.75/1）+ 空 gold 强制二元 + `temperature=0`，压住随机抖动。
- **标准做法该是什么**（说出来显专业）：自动评分做初筛，**关键结论做人工抽检**，算人机一致率（Kappa），一致率低说明要改 Judge 的 Prompt 而不是数据。**这一步我没做，是我该补的。**

**追问预判**：
- 「黑盒评测引擎，怎么知道它内部是怎么实现的？」→ 坦白：评测的是**端到端效果**，不看内部实现。这也是这类横评的意义——不管内部怎么设计，只看最终记忆能力。但**局限在于无法归因**，指标差的时候不知道是哪一步的问题，所以还要配合分步诊断。
