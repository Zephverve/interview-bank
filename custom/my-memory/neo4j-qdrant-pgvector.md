**题目**：Neo4j、Qdrant、pgvector 三个存储为什么要分开？不会太复杂吗？

### 回答

按数据类型分工，不是冗余。

- **Neo4j 存实体、关系和时序图谱**。多跳关系查询 —— 比如"这两个概念通过哪些中间实体关联起来" —— 是图数据库的主场，在向量库里根本做不了，在关系库里要写递归 CTE，性能和表达力都差。
- **Qdrant 存向量和轻量 payload**。高并发相似度检索，支持 filter 和向量联合查询。
- **PostgreSQL/pgvector 存结构化元数据、用户会话、权限，以及小规模的向量**。它以事务一致性见长，而且 pgvector 让它在小规模场景下可以直接顶替 Qdrant。

分工的代价是**运维复杂度上升**，三个组件要各自部署、监控、备份。

**关于一致性，这里我要诚实说**：跨存储的写操作目前是**两步写加 ID 关联加补偿重试**，我没有做分布式事务。这是这套架构真实的弱点 —— 如果写 Neo4j 成功但写 Qdrant 失败，会短暂出现图谱里有实体但检索不到向量的情况。补偿机制会重试，但重试窗口内确实有不一致。

如果让我改进，两个方向：一是引入 **outbox 模式**，把待写入的向量操作先落库，由后台任务消费，保证最终一致；二是建立**定期对账任务**，以向量 ID 为唯一真源，扫描出不一致的记录并修复。面试时我会主动把这个弱点讲出来，因为被追问到时才发现会显得心虚。
